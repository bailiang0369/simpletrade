# 事件合约 H=15 方向预测 · 实验日志

目标：ETH/BTC，无前视约束，≥65% 准确率，≥14 tpd（每天交易笔数）。

训练段 ≤ 2024-06-30；es 2024-06-30→2024-09-30；meta_val 2024-09-30→2025-09-30；test 2025-09-30→2026-08-29。

## 术语
- tp d = trades per day, 每日下注次数
- q = 置信度分位数阈值（滚动 30 天历史分布）
- ε = 收益阈值（过滤微幅振荡，|ret|>ε 才下注）
- AUC = ROC-AUC 全样本
- Acc = 选中样本的方向命中率（方向正确/总选）

### 经验（从失败中提炼）

1. **硬分类 AUC 天花板 ~0.534**：当前 58 特征 + LGB，无论怎么堆 seed/模型族，AUC 稳在 0.534-0.543 区间，树结构表达力已到顶。
2. **集成边际递减**：LGB 10seed → +2pp；LGB+XGB 20seed → 0.0pp；+CAT 30seed → +0.3pp。相关性太高。
3. **原始序列（GRU/CNN）不自动优于手工特征**：除非网络足够深/足够数据，CPU 上 23.5万样本/降采样过轻，GRU 反而过拟合。
4. **回归目标不能用 AUC 评估**：要用 Spearman 排名相关 / IC，再通过单调性映射回概率。
5. **微幅振荡是标签噪声**：close[t+15] > close[t] 含大量 ret=0.001% 的样本，其方向标签本身不可预测，必须过滤。
6. **阈值必须在 meta_val 选**：不能反复扫 test。

## 🔬 当前尝试（2026-09-22 下午）

### 线 A：过滤微幅振荡 + 回归 LGB + 重新打分

**假设**：
- |ret| < ε 的样本，标签本身是噪声（振荡 + 舍入误差），模型学不到东西
- 用回归目标直接学 ret（或 soft_label），评估用 Spearman/IC，最终单调性映射

**方法**：
1. 重新生成标签：保留全样本用于训练，但推理时**只在 |ret|（历史估计）高于阈值 ε 的时点下注**
2. 训练：LGB 回归 soft_label（ret 压缩到 [0,1]），评估 Spearman on es
3. 阈值搜索：meta_val 扫 ε ∈ {0, 0.0003, 0.0005, 0.001, 0.0015} + q ∈ {98, 98.5, 99, 99.2, 99.5}
4. 锁死 (ε*, q*) 后 test 只跑一次

**状态**：进行中

---

### 线 B：阈值正规化

**之前问题**：每次评估都在 test 扫 q 值，隐式前视。

**修正**：
1. 在 meta_val 网格搜 (ε, q) 找 (65% acc, ≥14 tpd) 最优组合
2. 锁死参数后 test 做**一次且仅一次**无前视评估

**状态**：待线 A 完成后衔接

---

### 线 C：spearman-regression LGB

**假设**：用 soft_label 做回归目标（不是硬分类），LGB 的 `regression_objective` / `poisson` 训练后，预测值的排序质量（Spearman）应该优于 hard binary AUC。

**方法**：
1. soft_label = 0.5 + 0.5 * clip(ret_future / 0.02, -1, 1)（把未来收益归一到 [-2%, 2%] → [0,1]）
2. 训练：LGB `objective=regression`，eval_metric=Spearman / 直接用自定义 AUC on hard label 做 early_stop
3. 预测出来的 yhat 是软分数，直接用于排名（不用 sigmoid，因为训练目标不是概率）

**状态**：待跑

### 自适应阈值（在线反馈）

**假设**：近 N 天模型表现差就收紧 q，好就放松 q。
**结果**：meta_val ETH 最优 qb=98.5 qt=99.5 ql=97.5 lb=10 → acc=58.9%（反而下降）。
**失败原因**：近 N 天样本量太少（<200 笔），acc 估计噪声大，阈值抖动引入额外噪声。

### soft_label 回归 LGB

**假设**：回归目标比硬分类能利用更多连续信息。
**结果**：soft_label regression LGB hard AUC=0.512（比 binary 0.534 差 0.02）。
**失败原因**：H=15 方向本质是硬分类任务，回归会摊平标签并惩罚"极端正确"样本。

### 最终结论

**ETH H=15 事件合约方向预测，无前视约束下的真实可交易天花板**：
- **最好水平（ETH test q=99 无前视）：acc=63.22% tpd=14.2**
- **月度标准差 7.8pp**（稳定稳定性差）
- **BTC 天生更难**：acc 低 1-3pp

**核心瓶颈**：AUC 天花板 0.534（硬分类二值标签 + 58 维手工特征 + 树模型已榨干），无论换模型族、换回归目标、加 gate，都无法突破这个 AUC→acc 转化上限。

## 🚀 未来方向建议（如果要继续冲 65%）

按优先级排序：

1. **[最高ROI] 换 horizon 尝试**：H=5 分钟（更短，可能方向信号更强）、H=30 分钟（更长，可过滤噪声）。这是最快出结果的——换 `config.HORIZON=5/30` 重训即可。
2. **[高难度] 跨 horizon stacking**：同时训练 H=5/15/30 三个模型，meta-learner 用 3 个 P 做集成。
3. **[改口径] 接受 trade-off**：ETH q=99 无 gate tpd=14.2 → meta_val 调 q 到 99.2，tpd=11.6，test acc 有望 64-65%。
4. **[换资产] 放弃 BTC**：BTC 天生 harder（基础波动率低），ETH 单独做可能够 65%。
5. **[换数据] 加非技术特征**：订单簿深度、资金费率、OIA/多空比——如果能弄到。
6. **[深度学习] GRU + 更强正则 + 更多通道**（需要 GPU）。

### 统一条件
- 完整重训 ETH/BTC × H={5,15,30} × 10 seed LGB = 60 个模型
- 特征: features.py 56 维 (含 Stoch/RSI/MACD 技术指标 + 之前 38 维基础特征)

- 无前视: 滚动 30 天分位数阈值, 多空独立

### 方向 A: 换 horizon 重训 → 结果: H=15 仍然最好

| 币种 | horizon | es AUC | test AUC | test q=99 acc @ tpd |
|------|---------|--------|----------|---------------------|
| ETH  | 5       | 0.527  | 0.537    | **56.9%** @ 13.7t   |
| ETH  | 15      | **0.533** | **0.542** | **62.0%** @ 13.7t |
| ETH  | 30      | 0.530  | 0.543    | 59.7% @ 14.4t       |
| BTC  | 5       | 0.526  | 0.531    | 59.0% @ 14.3t       |
| BTC  | 15      | 0.533  | 0.536    | 60.1% @ 13.7t       |
| BTC  | 30      | 0.533  | 0.536    | **62.5%** @ 13.8t   |

**结论**: H=15 确实是 ETH 的最优 horizon。BTC h30 和 h15 AUC 相当，但 h30 test acc 更高（62.5% vs 60.1%）。H=5 方向信号最弱（AUC 0.527）。

### 方向 B: 跨 horizon stacking → 过拟合 meta_val，test 崩

**做法**: H5+H15+H30 各自 10-seed ens 的 P + conf 作为 meta 特征 (6 维)，meta_val 后 30% 切做 val 训 meta LGB (31 leaves, early_stop 50)。

| 币种 | meta_val AUC | meta_val q=99 | test AUC | test q=99 | 结论 |
|------|-------------|---------------|----------|-----------|------|
| ETH  | 0.542       | **66.4% @ 13.6t** ★ | 0.540 | **58.2% @ 13.6t** ❌ | meta_val 好看 test 崩 |
| BTC  | 0.538       | 63.8% @ 14.2t | 0.532 | 57.3% @ 14.3t ❌ | 同上 |

**失败原因**: meta LGB 在 meta_val 上学习了跨 horizon 的非线性交互，但 meta_val 的特征分布和 train 不同，堆叠出的过拟合模式迁移不到 test。

### 方向 B2: 简单平均 stacking → 无提升

ETH avg(h5,h15,h30) test AUC=0.5435，和单独 h15 0.5424 相当。q=99 acc=62.0%（几乎不变）。因为 h5 AUC 更低，稀释了 h15 的好信号。

### 方向 C: 更多 seed → 边际增益耗尽

额外训练 ETH h15 seed 115-250 (10 个)。
- 10 seed test AUC: **0.5424**
- 20 seed test AUC: **0.5424**
- meta_val 也是 0.5340 → 0.5343

**结论**: 10 seed 已经榨干 seed 多样性，再堆 seed 没用。

### 方向 D: 两币 conf 加权平均 → ⭐ 最大突破！

**核心发现**: 用两个最好的单 horizon 模型（ETH h15 和 BTC h30）的置信度 conf 做加权平均排名，方向仍用 ETH h15 的 P。

**ETH h15 conf = 0.6 × |P_eth_h15 - 0.5| + 0.4 × |P_btc_h30 - 0.5|**

| split | 方法 | q | acc | tpd | n |
|-------|------|---|-----|-----|---|
| test | **ETH h15 单独 conf (基线)** | 99 | **62.01%** | 13.7 | 4591 |
| test | **0.6*ETH+0.4*BTC conf 加权** | 99 | **64.78%** | 13.5 | 4506 |
| test | 同上 | 99.5 | **65.20%** | 7.2 | 2394 |
| test | 同上 | 99.7 | **66.82%** | 4.4 | 1477 |
| meta_val | ETH 单独 | 99 | 57.95% | 14.0 | 5110 |
| meta_val | 0.6*ETH+0.4*BTC | 99 | 60.90% | 13.9 | 5067 |

**提升幅度**: test q=99 从 62.01% → 64.78%，**+2.77pp**。离 65% 只差 0.22pp！

**为什么有效**: BTC h30 的 conf 给 ETH 信号提供了**正交的市场 regime 信息**。当 BTC h30 也有高 conf 时，ETH h15 的高 conf 更可信。加权平均避免了 stacking 的过拟合（没有额外训练参数）。

### 方向 E: 两币 gate (ETH∩BTC 同向) → acc ↑ 但 tpd ↓

test 上:
- qe=97, qb=97: 62.62% @ 11.1t (一般)
- qe=99.5, qb=97: **65.75%** @ 3.6t (acc 够但 tpd 远不够)
- qe=98.5, qb=97: 63.57% @ 7.5t

单独 gate 方法只能牺牲 tpd 换 acc，不如 conf 加权平均优雅。

### meta_val vs test 巨大差异 — 关键洞察

| 配置 | meta_val q=99 | test q=99 | gap |
|------|--------------|-----------|-----|
| ETH h15 单独 | 57.95% | 62.01% | **+4.06pp** |
| ETH+BTC conf 加权 | 60.90% | 64.78% | **+3.88pp** |
| BTC h30 单独 | 58.75% | 62.47% | **+3.72pp** |

**meta_val (2024-09-30 → 2025-09-30) 比 test 难 ~4pp**。任何基于 meta_val 调出来的参数在 test 上都会偏保守。这意味着:
- 想在 test 上达到 65% acc，meta_val 上最好能到 ~61-62%
- 当前 meta_val best = 62.24% (w=0.7, q=99.3) → test 应该 ~66%？
  实际上 test q=99.3 是 64.56%。gap 不完全稳定。

## 为什么没有到 65%? — 瓶颈分析

1. **单模型 AUC 天花板 0.534 (hard binary)**。从 AUC 到 top-1% acc 的映射:
   - 理论: acc ≈ 0.5 + 2*(AUC-0.5)*logit ≈ 0.5 + 2*0.034 ≈ 56.8%
   - 实际 q=99 (top 1%): 62-64% — 实际排序质量比 AUC 反映的好
   - 实际 q=99.9 (top 0.1%): 67-70%

2. **AUC 天花板来自特征信息密度**。56 维特征已经榨干了价格/成交量/波动率的统计规律。更多特征 (Stoch/RSI/MACD 等) 加了没帮助。

3. **跨 horizon stacking 过拟合**。虽然 meta_val 上到 66.4%，但 test 只有 58.2%，说明跨 horizon 的非线性交互在不同时间段不稳定。

4. **meta_val/test gap** 导致任何在 meta_val 上选出的最优参数在 test 上都保守了 3-4pp。

## ⚠️ 2026-09-22 晚 严格无前视复查（纠正之前的过拟合）

### 问题: conf 加权 w=0.6 是怎么选出来的?

之前的 w=0.6 是在 **test 上同时扫 w 和 q 选出来的** — 这就是前视泄漏 (lookahead leakage)。**meta_val→test 这种正确流程应该是 meta_val 上选 w+q, 锁死, 然后 test 只跑一次。**

### 严格无前视重跑结果

| 组合 | meta_val 扫 (w*, q*) | test acc @ tpd | 同 q 基线 | conf 加权真实提升 |
|------|---------------------|----------------|-----------|------------------|
| ETH h15 + BTC h30 | w=0.90 q=99.7 | **66.42%** @ 4.4t | 65.31% | **+1.11pp** (但 tpd 只有 4.4) |
| ETH h15 + BTC h15 | w=0.30 q=99.1 | **62.83%** @ 12.3t | 62.65% | **+0.18pp** (几乎没用) |
| BTC h30 + ETH h15 | w=0.90 q=99.6 | **66.09%** @ 5.9t | 66.80% | **-0.71pp** ❌ 反效果 |
| (之前泄漏的) ETH+B30 | **w=0.60 q=99.0** | **64.78% @ 13.5t** | 62.01% | **+2.77pp ← 是泄漏出来的假提升** |

### 纠正结论

1. **conf 加权不是通用方法**: 只在 ETH h15 + BTC h30 高 q (99.7) 低 tpd 区间有 +1pp 真实提升; BTC 下注方向上**反效果 -0.7pp**; BTC h15 参考信号几乎没用。

2. **w 值过拟合**: meta_val 上 ETH+B30 扫不出 acc≥62 + tpd≥10 的合格组合, 最佳 w=0.90 说明 conf 加权主要还是靠下注主体自己的 conf, 参考信号只占 10%。**之前选 w=0.6 是对 test 分布的过拟合**。

3. **真实天花板**: ETH h15 单独 conf q=99 → **62.01% @ 13.7t**, 这才是严格无前视下的基线。任何 conf 加权的真实提升 ≤ +1pp, 且伴随 tpd 大幅下降。

4. **之前实验日志里 64.78% 的数字作废**, 那个是 test 上扫参数的结果, 不能算。

### 关于 BTC 下注反向

BTC h30 下注 + ETH h15 conf 参考, conf 加权反而 **-0.71pp**。原因:
- BTC 市场状态转换比 ETH 滞后 (BTC 是更"慢"的品种)
- ETH 的高 conf 时点对应 BTC 的早期信号, 但 BTC 模型自己的 conf 已经捕捉到了
- 加入 ETH conf 等于在 BTC 排名里混入了噪声

### 关于其他 horizon

同理: 任何跨 horizon conf 加权都要**每个 horizon 组合分别在 meta_val 上做严格参数锁定**, 不能假定"ETH h15 + BTC h30 有效"就"ETH h5 + BTC h15 也有效"。每个组合的最优 w 可能完全不同, 而且大多数组合可能是反效果。

## 🔬 2026-09-22 深夜 · 单模型单币种突破 ETH h15 → 65% 任务

**目标**: ETH h15 单独 LGB 无前视，test ≥65% acc + ≥14 tpd

**核心假设**: AUC 天花板 0.534 是因为 hard binary label + 固定 56 维特征 + 固定超参数。可以通过以下方式突破：

5. 标签去噪 (只在 |ret|>ε 样本上训练)
6. 换 CatBoost 调参

## 🔬 2026-09-22 深夜 · 单模型 ETH h15 突破 65% 任务

**baseline (重训确认)**: ETH h15 10-seed LGB, nL=63, mD=200, lr=0.05, fF=0.8, bF=0.8
- meta_val AUC=0.5340, q=99 → 57.95% @ 14.0t
- test AUC=0.5424, q=99 → 62.01% @ 13.7t

### 方向 1: num_leaves 超参数网格 (全部 params 独立 Dataset, 无复用 bug)

| nL | mD | lr | meta_val AUC | test AUC | test q=99 | test q=99.5 |
|----|----|----|-------------|----------|----------|-------------|
| 63 | 200| .05| 0.5341 | 0.5421 | 60.59% @ 13.8t | 63.87% @ 7.0t |
| 127| 200| .05| 0.5343 | 0.5422 | 61.98% @ 13.5t | 63.91% @ 7.1t |
| 255| 200| .05| **0.5345** | **0.5423** | **62.03% @ 13.6t** | 64.29% @ 7.0t |

**发现**: num_leaves 增大 (63→255) meta_val AUC +0.0004, test AUC +0.0002, 但 test q=99 acc 从 60.59% → 62.03% (+1.44pp)。**AUC 相同但 tail 排序可以显著不同** — 更细的叶子切分可能让 top 1% 样本排序更准, 即使整体 AUC 一样。

**结论**: num_leaves 255 略好, 边际提升但没有质的变化。

### 方向 2: min_data_in_leaf (固定 nL=127)

| mD | meta_val AUC | test AUC | test q=99 | test q=99.5 |
|----|-------------|----------|----------|-------------|
| 50 | — (early_stop 较早) | — | — | — |
| 200| 0.5343 | 0.5422 | 61.98% @ 13.5t | 63.91% @ 7.1t |
| 500| 0.5343 | 0.5423 | 61.15% @ 13.6t | 64.44% @ 6.9t |

**结论**: mD 对 AUC 影响很小, 主要改变 best_iteration 和排序尾部。

### 方向 3: 标签去噪 (只训练 |ret| > ε 的样本) ⭐ 最有价值

| ε | 训练样本占比 | meta_val AUC | test AUC | test q=99 | test q=99.5 |
|---|-------------|-------------|----------|----------|-------------|
| 0 (全量) | 100% | 0.5343 | 0.5422 | 61.98% @ 13.5t | 63.96% @ 7.1t |
| 0.0005 | 82.0% | 0.5340 | **0.5429** | 62.37% @ 13.8t | 65.19% @ 6.9t ← ★★★ |
| 0.001 | 66.4% | 0.5338 | 0.5423 | 62.79% @ 13.2t | 63.41% @ 7.0t |

**发现**: ε=0.0005 是 sweet spot — 训练时丢掉 ret<0.05% 的噪声样本 (82% 保留), **test AUC 从 0.5422 → 0.5429 (+0.0007)**。这 0.0007 的 AUC 提升对应 test q=99.5 acc **从 63.96% → 65.19% (+1.23pp)** — 终于到 65%+!

**为什么 meta_val AUC 反而降了 (0.5343 → 0.5340)?**
- meta_val 是熊市 (2024-09 → 2025-09), ret 普遍较小, 去噪丢了 18% 样本影响更大
- test 是牛市 (2025-09 → 2026-09), ret 分布更广, 去噪效果好
- 这是一个**跨 regime 迁移的真实差异**, 不是过拟合

**但 meta_val 上 ε=0.0005 q=99 只有 58.38% @ 14.2t, 选不到这个配置!**
- 严格无前视的话, meta_val 上找不到 acc≥65 + tpd≥14 的 ETH h15 配置
- 去噪 ε=0.0005 在 test 上很好, 但 meta_val 上 acc 只有 58-59%
- 这意味着: **严格无前视下, ETH h15 无法通过参数选择达到 65%**

### 方向 4: regression 目标 (predict ret, 硬 AUC 做 early_stop) ❌ 彻底失败

| | meta_val AUC | test AUC | test q=99 |
|--|-------------|----------|-----------|
| regression | **0.4847** | **0.4810** | 48.93% |

**回归模型预测 ret_future 的 AUC < 0.5, 等同于随机。** 之前实验日志里说 soft_label regression AUC 0.512, 这次更惨 0.481。

**失败原因**: H=15 的 ret_future 是噪声主导, 回归目标把模型的排序能力摊平了。binary 目标让模型专注在"涨/跌"方向判断, 回归让模型同时要猜幅度, 分散了精力。

### 方向 5: rank objective ❌ 技术障碍

LightGBM 4.7.0 不支持 `rank:pairwise` 这个 objective 名 (要 `lambdarank`), 但 lambdarank 需要 group 约束 (每组查询 ≤ 10000 行), 设置复杂, 跳过。

最好的 test 结果 **62.03% @ 13.6t**, 离 65% 差 2.97pp。

### 不严格无前视 (直接在 test 上扫参数) — 仅供参考, 不能用于生产

| 方法 | test AUC | test acc @ tpd | 备注 |
|------|----------|----------------|------|
| 去噪 ε=0.0005, q=99.5 | 0.5429 | **65.19% @ 6.9t** | acc 够但 tpd 不够 |
| 去噪 ε=0.0005, q=99.4 | 0.5429 | **65.20% @ 8.2t** | tpd 还是不够 |

### 关键瓶颈 (按优先级)

1. **AUC 天花板 0.5429** — 再高 0.002 就能把 q=99 acc 推到 65%。当前所有方法 (超参数/去噪/目标函数) 只能在 0.5421-0.5429 之间波动。

2. **meta_val/test gap ~4pp** — meta_val 那段是熊市, 信号更弱。这意味着任何在 meta_val 上能到 62% 的配置, test 上实际可能到 66%。但前提是 meta_val 上真的能找到这个配置。

3. **tpd vs acc trade-off 不可避免** — 想让 acc 从 62% 到 65%, q 必须从 99 升到 99.4+, tpd 从 13.5 降到 8.2。
